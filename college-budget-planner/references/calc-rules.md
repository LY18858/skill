# 分配规则与边界

本文档解释 `scripts/budget_calc.py` 的计算逻辑。**不要在对话里手算**，本文只用于理解与解释结果。

## 一、基础定义

```text
固定开销 = 宿舍杂费 + 话费 + 交通 + 校园网 + 订阅
可分配剩余 R = 生活费 − 固定开销 − 本月大额支出
三餐下限 = 在校天数 × 30 元（早 6 + 午 12 + 晚 12），默认 28 天 = 840 元
```

宿舍杂费按月份自动切换（长沙）：

| 子项 | 过渡季（3–5 月、10–11 月） | 空调季（6–9 月制冷、12–2 月取暖） |
|------|------|------|
| 洗澡热水 | 40 | 45 |
| 饮用水 | 25 | 25 |
| 洗衣 | 25 | 30 |
| 电费均摊 | 30 | 60 |
| 合计 | **120** | **160** |

住宿费含在学年学费中，不计入月度生活费；用户主动要求分摊时才折算。

## 二、基准比例

| 板块 | 比例 |
|------|------|
| 三餐伙食 | 52% |
| 日常零碎 | 10% |
| 娱乐社交 | 18% |
| 储蓄 | 12% |
| 应急备用金 | 8% |

合计 100%。允许按消费偏好上下浮动 3 个百分点，但**储蓄 + 应急合计不得低于 18%**。

## 三、取整与兜底

1. 三餐、日常零碎、娱乐社交、储蓄四块四舍五入到 10 元（脚本用 `int(x/10+0.5)*10`，避开银行家舍入）。
2. **应急备用金 = R − 四块之和**，是兜底项，不独立取整。
3. 应急占 R 的合理区间为 6%–10%：
   - 低于 6% → 依次从娱乐社交、日常零碎、储蓄挪钱补足；
   - 高于 10% → 超出部分回拨给储蓄。
4. 五个板块之和必须等于 R；固定开销 + R 必须等于生活费。脚本 `balanced` 字段即此校验。

## 四、四种模式

按下述顺序判定，命中即停：

| 判定条件 | 模式 | 分配方式 |
|----------|------|----------|
| R ≤ 0 | `deficit` | 全部归零，报「方案不可行」，要求调整大额支出 |
| R < 三餐下限 | `meal_deficit` | 三餐 = R（仍不够），其余归零，报缺口金额 |
| R < 三餐下限 + 100 | `extreme_tight` | 三餐 = 下限，应急 = R − 下限，其余归零 |
| R < 三餐下限 × 1.25 | `tight` | 三餐 = 下限，日常零碎 = 50，应急 = 余数，娱乐与储蓄归零 |
| 其他 | `normal` | 按基准比例分配 |

**下限保护**：`normal` 模式下若 52% 算出低于三餐下限，把三餐补到下限，
剩余金额按「日常零碎:娱乐社交:储蓄:应急 = 10:18:12:8」归一化重分，并保证应急不低于 6%。
这通常意味着大额支出挤压了吃饭，必须触发第 3 段的取舍方案。

## 五、大额支出调整的触发条件

任一成立即必须给取舍方案（对应脚本 `trigger_large_adjust = true`）：

1. 固定开销 + 大额支出 > 生活费 × 70%；
2. 三餐被压到下限以下，或已进入 `tight / extreme_tight / meal_deficit / deficit`；
3. `normal` 模式下 52% 分配不足三餐下限（说明实际挤压了吃饭）；
4. 储蓄 + 应急合计 < 生活费 × 10%。

取舍方案的优先级固定为：
**保吃饭 > 保刚需（宿舍杂费/交通/话费）> 保储蓄（至少留 5%）> 砍娱乐 > 砍日常零碎**。

## 六、常见错误

- ❌ 把「固定开销 115 元」当成含宿舍杂费的总额（宿舍杂费要另加）。
- ❌ 用银行家舍入导致 85 元变 80 元。
- ❌ 尾差丢给应急后不做 6%–10% 校验，导致应急虚高、储蓄虚低。
- ❌ 三餐被挤压时仍按 52% 硬出表，得到一个「看起来正常但吃不饱」的方案。
